线程局部存储（TLS）与 TLS 回调函数

这里的 TLS 不是 Transport Layer Security，而是 Thread Local Storage，也就是线程局部存储。它本来是 Windows 用来解决多线程数据隔离的机制，但在逆向里经常和反调试联系在一起，因为 TLS 回调函数会在程序入口点之前执行。

线程局部存储

在多线程程序里，普通全局变量是所有线程共享的。如果多个线程同时读写同一个全局变量，就可能互相覆盖。

TLS 的思路很直接：让每个线程都拥有同一个变量的独立副本。

也就是说，变量名看起来一样，但不同线程访问到的是不同数据。

此时每个线程都有自己的 last_error。A 线程写入 1001，B 线程写入 2002，它们互不影响。

这和 GetLastError() 的行为很像。每个线程都有自己的错误码，所以 A 线程的错误不会覆盖 B 线程。

TLS 回调函数

TLS 另一个更关键的点是 TLS 回调函数。

PE 文件可以注册一组 TLS callback。系统加载程序时，会在进入 main / WinMain 之前调用这些回调函数。

函数原型和 DllMain 类似：

常见 Reason 有：

Reason 含义
DLL_PROCESS_ATTACH 进程启动
DLL_THREAD_ATTACH 新线程创建
DLL_THREAD_DETACH 线程退出
DLL_PROCESS_DETACH 进程退出

重点在第一项：进程启动时，TLS callback 会比入口点更早执行。

这也是它常用于反调试的原因。

其中 AddressOfCallBacks 指向 TLS 回调函数指针数组，并且数组以 NULL 结尾。

逆向时可以直接用 CFF Explorer、PE-bear 或者 IDA 看 TLS Directory。如果 AddressOfCallBacks 非空，就说明程序注册了 TLS 回调。

绕过

知道它在哪里执行，绕过思路也就清楚了。

常见方法：

  1. 在系统断点停下，不要等到程序入口点
  2. 找到 TLS Directory，看 AddressOfCallBacks
  3. 在回调地址下断点，单步分析
  4. Patch 回调数组，把第一项改成 NULL
  5. Patch 检测逻辑，让它不退出
  6. 修改 PEB 中的调试标志

总结

线程局部存储本身是一个多线程机制，用来让不同线程拥有独立数据。

但 TLS 回调函数会在入口点之前执行，这就给反调试提供了一个很好的时间点。逆向时如果程序还没进 main 就退出，或者入口点前已经发生了异常行为，就应该先看 PE 的 TLS Directory。

看到 AddressOfCallBacks 非空，就要意识到：真正的逻辑可能在入口点之前就已经开始了。
