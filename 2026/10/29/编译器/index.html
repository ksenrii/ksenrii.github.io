编译器

编译器（compiler）是一种计算机程序，它会将某种编程语言写成的源代码( 原始语言）转换成另一种编程语言（目标语言）。

它主要的目的是将便于人编写、阅读、维护的高级计算机语言所写作的源代码程序，翻译为计算机能解读、运行的低阶机器语言的程序，也就是可执行文件。

编译器将原始程序（source program）作为输入，翻译产生使用目标语言（target language）的等价程序。源代码一般为高级语言（High-level language），如Pascal、C、C++、C# 、Java等，而目标语言则是汇编语言或目标机器的目标代码（Object code），有时也称作机器代码（Machine code）。

一个现代编译器的主要工作流程如下：

源代码（source code）→ 预处理器（preprocessor）→ 编译器（compiler）→ 汇编程序（assembler）→ 目标代码（object code）→ 链接器（linker）→ 可执行文件（executables），最后打包好的文件就可以给电脑去判读执行了。

分类

编译器的一种分类方式是按照生成代码所运行的系统平台划分，这个平台称为目标平台。

有一些编译器输出的代码，将运行于与编译器所在相同类型的计算机和操作系统之上，这种编译器叫做本地编译器。输出可以运行于不同的平台之上的编译器，叫做交叉编译器。由于嵌入式系统通常没有软件开发环境，因此，为这类系统开发软件时，通常需要使用交叉编译器。

编译器所输出于虚拟机上运行之代码，编译器和编译器输出的运行平台有可能相同，也有可能不同。因此，对于这类编译器，不去区分它是本地编译器还是交叉编译器。

GCC

GCC（GNU Compiler Collection），即 GNU 编译器套件，是 GNU 项目开发的一套开源编译器工具集。

GCC 最初的含义是 GNU C Compiler（GNU C 编译器），后来随着对更多编程语言的支持，其名称变为 GNU Compiler Collection。

GCC 不仅支持 C 语言，还支持 C++、Fortran、Ada、Go 等多种编程语言，同时支持 x86、ARM、RISC-V 等多种处理器架构。

需要注意的是，GCC 并不等同于 gcc 命令。GCC 是整个编译器套件，而 gcc 是我们通常用于调用 C 编译工具链的驱动程序。对于 C++ 程序，通常使用 g++。

GCC 的编译过程

使用 GCC 编译 C 语言程序，通常需要经历以下四个阶段：

  1. 预处理（Preprocessing）：处理宏定义、头文件包含以及条件编译指令。
  2. 编译（Compilation）：对源程序进行分析与优化，并生成汇编代码。
  3. 汇编（Assembly）：将汇编代码转换成机器码，生成目标文件。
  4. 链接（Linking）：将目标文件、库文件等组合起来，生成可执行程序。

GCC 提供了不同的命令行参数，可以让编译过程停留在指定阶段。

需要注意，main 函数通常不是 ELF 程序的实际入口点。程序一般先经过运行时启动代码，完成必要的初始化，再调用 main 函数。

Clang

Clang 是 LLVM 项目中的 C 语言家族编译器前端，主要支持 C、C++、Objective-C 和 Objective-C++ 等语言。

与 GCC 类似，Clang 也能够完成预处理、编译、汇编和链接等过程。但两者的内部实现有所不同：GCC 使用 GIMPLE、RTL 等自己的中间表示，而 Clang 通常将源代码转换为 LLVM IR，再利用 LLVM 提供的优化器和后端生成目标机器代码。

clang 可执行文件实际上是一个编译驱动程序（Compiler Driver），负责组织编译器、汇编器和链接器等工具的执行过程。

Clang编译过程

  1. Driver（驱动程序）：根据输入文件及编译参数，组织整个编译过程。
  2. Preprocessing（预处理）：完成 Tokenization（词法单元化）、宏展开和头文件包含等操作。
  3. Parsing and Semantic Analysis（语法分析与语义分析）：解析源代码，检查语法和类型等规则，构建抽象语法树（AST）。
  4. Code Generation and Optimization（代码生成与优化）：将 AST 转换为 LLVM IR，经过优化及目标相关的代码生成，最终得到机器指令。
  5. Assembler（汇编）：将汇编指令转换为目标文件。
  6. Linker（链接）：将目标文件与所需的库进行链接，生成可执行文件或动态库

下一步，Clang 会通过 CodeGen 将 AST 转换为 LLVM IR（Intermediate Representation，中间表示）。

LLVM 优化器可以在 IR 上执行优化，随后 LLVM 后端将其转换为目标架构的机器代码。

第一部分是模块信息

ModuleID：模块标识。

source_filename：源文件名称。

target datalayout：描述目标平台的数据布局，如字节序、数据对齐等。

target triple：目标平台，这里是 x86-64 Linux。

第二部分是函数定义

define：定义函数。

i32：32 位整数类型。

@main：函数名称。

#0：引用后面的函数属性组。

alloca：在栈上分配内存。

store：将整数 0 写入分配的内存。

ret i32 10：返回整数 10。

其中 alloca 和 store 是 Clang 在 -O0 下生成的辅助操作，不影响最终返回值。

第三部分是函数属性

noinline：禁止函数内联。

nounwind：函数不会向调用者传播异常展开。

optnone：禁用常规优化。

uwtable：要求生成栈展开信息。

第四部分是模块化数据

用于记录 PIC、PIE、编译器版本等附加信息，不属于实际执行的指令。

llvm

为了醋,包的饺子终于来了

LLVM（LLVM Project） 是一个开源的模块化编译器基础设施项目，提供了编译优化、代码生成、程序分析等功能所需的工具和库

LLVM 最初是 Low Level Virtual Machine 的缩写，但随着项目的发展，LLVM 已成为项目名称，不再被视为一个首字母缩写词

与 GCC 这样的完整编译器套件不同，LLVM 的核心主要提供编译器基础设施。它可以配合不同的语言前端，将源代码转换为中间表示，再通过优化器和后端生成目标机器代码。

LLVM 项目包含多个子项目，例如：

组件 作用
LLVM Core 中间表示、优化器、代码生成等核心基础设施
Clang C、C++、Objective-C 等语言的编译器前端
LLD LLVM 项目的链接器
LLDB 调试器
libc++ C++ 标准库实现
compiler-rt 编译器运行时支持库

LLVM 的一个重要特点是采用模块化设计，不同语言的编译器前端可以复用 LLVM 提供的优化器和代码生成后端。

官方文档：Getting Started with the LLVM System

llvm架构

LLVM 编译框架通常可以从逻辑上划分为三个部分：

Frontend（前端）：对源代码进行词法分析、语法分析和语义分析，并生成中间表示

Middle-end（中端）：对 LLVM IR 进行程序分析与优化

Backend（后端）：将中间表示转换为目标架构的机器代码

\[ \boxed{\text{C/C++ 源代码}} \xrightarrow{\text{Clang Frontend}} \boxed{\text{LLVM IR}} \xrightarrow{\text{LLVM Optimizer}} \boxed{\text{Optimized LLVM IR}} \xrightarrow{\text{LLVM Backend}} \boxed{\text{汇编 / 机器码}} \xrightarrow{\text{Assembler}} \boxed{\text{目标文件}} \xrightarrow{\text{Linker}} \boxed{\text{可执行程序}} \]

其中，LLVM IR 是连接前端、中端和后端的重要中间表示

在这种架构下，前端主要负责理解源语言，优化器负责分析和转换程序，后端则负责生成特定 CPU 架构的机器代码

这种设计使得 LLVM 能够支持 x86-64、AArch64、RISC-V 等多种处理器架构

LLVM IR

LLVM IR（Intermediate Representation） 是 LLVM 使用的中间表示，用于描述程序的函数、基本块、指令、数据类型及控制流

LLVM IR 主要有三种表现形式：

LLVM Pass

LLVM Pass 是 LLVM 中用于分析或转换程序的基本处理单元。

按照主要用途，可以分为：

  • Analysis Pass（分析 Pass）：分析程序结构和属性，例如控制流、循环等。
  • Transformation Pass（转换 Pass）：修改程序的中间表示，例如常量传播、死代码消除和循环优化。

LLVM Backend

LLVM 后端负责将 LLVM IR 转换为目标架构的机器代码。

其主要工作包括：

  1. Instruction Selection（指令选择）：将中间表示转换为目标架构支持的指令。
  2. Register Allocation（寄存器分配）：将虚拟寄存器映射到物理寄存器。
  3. Instruction Scheduling（指令调度）：根据目标处理器的特点安排指令执行顺序。
  4. Machine Code Emission（机器码生成）：生成汇编代码或目标文件。

例如，同一段 LLVM IR 可以通过不同的后端生成 x86-64 或 AArch64 指令

这也是 LLVM 能够用于交叉编译的重要原因之一
