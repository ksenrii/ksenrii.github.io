PEB

本章将学习有关 PEB（Process Environment Block，进程环境块）的知识。

PEB 是存放进程信息的结构体，尺寸非常大，其大部分内容都已被文档化。本章只讲解它的几个重要成员，调试中会经常接触。

PEB的重要成员

PEB 结构体非常庞大，且结构复杂，我们只简单讲解其中几个与代码逆向分析相关的重要成员。

PEB.BeingDebugged

Kernel32.dll 中有个名为 Kernel32!IsDebuggerPresent() 的 API，但普通的应用程序开发中并不常用。

顾名思义，该 API 函数用于判断当前进程是否处于调试状态，并返回判断结果。

该 API 通过检测 PEB.BeingDebugged 成员来确定是否正在调试进程（是，则返回 1；否，则返回 0）。

下图中显示IsDebuggerPresent()API的代码

第一条指令获取当前进程的PEB地址,存到eax,再把eax+2的值(PEB+2)存到eax并返回

我们又知道PEB+2=PEB.BeingDebugged

所以 IsDebuggerPresent() 本质就是：return PEB->BeingDebugged

提示

Windows 7 中，IsDebuggerPresent() API 是在 Kernelbase.dll 中实现的。而在 Windows XP 及以前版本的操作系统中，它是在 kernel32.dll 中实现的。

在我的电脑环境中，PEB 结构体的地址为 0024D000，所以 PEB.BeingDebugged 成员的地址为 0024D002

看返回值,其值为 1（TRUE），如上图所示，表示当前进程处于调试状态。

该值在代码逆向分析领域主要用于反调试技术。检测该值，若进程处于调试中，则终止进程。知名例所见，这是一种非常简单的基础反调试技术。

PEB.Ldr

PEB.Ldr 成员是指向 _PEB_LDR_DATA 结构体的指针。借助 WinDbg 调试器查看 _PEB_LDR_DATA 结构体成员，如下所示。

PEB_LDR_DATA结构体

当前模块（DLL）加载到进程后，通过 PEB.Ldr 成员可以直接获取该模块的加载基地址，所以 PEB.Ldr 是非常重要的成员。

_PEB_LDR_DATA 结构体成员中有 3 个 _LIST_ENTRY 类型的成员：

LIST_ENTRY结构体

从上述结构体的定义可以看到，_LIST_ENTRY 结构体提供了双向链表机制。

那么链表中保存着哪些信息呢？是 _LDR_DATA_TABLE_ENTRY 结构体的信息。该结构体的定义如下所示。

每个加载到进程中的 DLL 模块都有与之对应的 _LDR_DATA_TABLE_ENTRY 结构体，这些结构体相互链接，最终形成 _LIST_ENTRY 双向链表。

需要注意的是，_PEB_LDR_DATA 结构体中存在 3 种链表。也就是说，存在多个 _LDR_DATA_TABLE_ENTRY 结构体，并且有 3 种链接方法可以将它们链接起来。

简单来说

PEB.Ldr 就是进程的“模块列表入口”，里面通过双向链表记录了当前进程加载的 EXE 和 DLL。

PEB.ProcessHeap & PEB.NtGlobalFlag

PEB.ProcessHeap 与 PEB.NtGlobalFlag 成员（像 PEB.BeingDebugged 成员一样）应用于反调试技术。

若进程处于调试状态，则 ProcessHeap 与 NtGlobalFlag 成员就持有特定值。由于它们具有这一特征，所以常常应用于反调试技术。
