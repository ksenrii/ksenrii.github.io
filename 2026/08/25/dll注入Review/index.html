这篇快速回顾 Windows 消息钩取、DLL 注入与卸载，以及通过修改 PE 导入表加载 DLL 的方法。

DLL注入

DLL 注入就是把指定 DLL 强制加载到其他进程的地址空间中。

运行时注入的核心可以概括为：

DLL 被加载后，Windows 装载器会调用它的 DllMain()。当 dwReason 为 DLL_PROCESS_ATTACH 时，便可以执行初始化代码。

本篇涉及 4 种加载思路：

方法 谁负责加载 DLL 特点
CreateRemoteThread() 自己控制目标进程调用 LoadLibrary() 目标明确，步骤最完整
AppInit_DLLs user32.dll 根据注册表加载 影响范围大，依赖系统配置
SetWindowsHookEx() Windows 在触发消息钩子时加载 适合消息钩取，也是一种 DLL 注入
修改 PE 导入表 PE 装载器根据 IDT 加载 修改一次，以后启动时自动加载

Windows消息钩取

Windows GUI 使用消息驱动。键盘事件产生后，消息会从 OS 消息队列进入应用程序消息队列，应用程序再取出并处理消息。

消息钩子位于两者之间，因此可以先于应用程序查看、修改或拦截消息。多个同类钩子按顺序组成 Hook Chain。

SetWindowsHookEx

重点关注 4 个参数：

  • idHook：钩子类型，本例为 WH_KEYBOARD；
  • lpfn：钩子回调函数，本例为 KeyboardProc；
  • hMod：回调函数所在 DLL 的模块句柄；
  • dwThreadId：目标线程 ID，设为 0 表示全局钩子。

全局钩子的回调函数需要放在 DLL 中。目标进程发生对应消息时，Windows 会把该 DLL 加载到目标进程，再调用钩子过程。

KeyHook.dll流程

钩子安装后，发生键盘消息的进程会加载 KeyHook.dll，然后由 Windows 调用 KeyboardProc()。

  • 返回 1：截断消息，记事本无法收到键盘输入；
  • 调用 CallNextHookEx()：把消息继续交给下一个钩子或目标程序。

停止时调用 UnhookWindowsHookEx() 拆除钩子，再由 FreeLibrary() 卸载 KeyHook.dll。

修改PE导入表加载DLL

前面的方法都在程序运行时完成注入。另一种思路是直接修改磁盘上的 PE 文件，在导入表中注册新的 DLL。

本例修改 TextView.exe，得到 TextView_Patch.exe。以后每次运行修改后的文件，Windows 装载器都会根据 IDT 自动加载 myhack3.dll。

整个过程如下：

IMAGE_IMPORT_DESCRIPTOR

IDT（Import Directory Table）本质上是 IMAGE_IMPORT_DESCRIPTOR 数组，每个 DLL 对应一个结构体，数组最后以全 0 结构结束。

重点关注 3 个成员：

  • OriginalFirstThunk：指向 INT，记录要导入哪些函数；
  • Name：指向 DLL 名称字符串；
  • FirstThunk：指向 IAT，程序运行后由装载器写入函数的实际地址。

本例让 myhack3.dll 导出一个没有实际功能的 dummy()，再由 TextView_Patch.exe 导入它。这样装载器就会加载 myhack3.dll，真正的代码则在 DLL_PROCESS_ATTACH 时开始执行。

DLL调试

调试被注入的 DLL 时，可以按下面的顺序操作：

  1. 使用调试器运行或 Attach 到目标进程；
  2. 开启 DLL Load 或用户 DLL 入口断点；
  3. 执行注入、安装消息钩子或运行修改后的 PE；
  4. DLL 被加载时调试器暂停；
  5. 转到 DLL 的 EP、DllMain() 或钩子回调函数继续分析。

这里需要调试的是目标进程，因为 DLL 最终运行在目标进程的地址空间中。
