# 代码逆向基础

软件逆向工程（代码逆向分析）是一种探究应用程序内部组成结构及工作原理的技术。运用逆向分析技术，我们可以轻松窥探程序内部结构，掌握其工作原理，可以在程序的开发与测试阶段发现 Bug 和漏洞，并直接修改程序文件或内存解决这些问题，还可以为程序添加新功能，使程序更强大。

其中分析可执行文件时使用的方法大致分为两种：静态分析法和动态分析法。

## 静态分析法

静态分析法是在不执行代码文件的情形下，对代码进行静态分析的一种方法。静态分析时并不执行代码，而是观察代码文件的外部特征，获取文件的类型（EXE、DLI、DOC、ZIP 等）、大小、PE 头信息、Import/Export API、内部字符串、是否运行时解压缩、注册信息、调试信息、数字证书等多种信息。此外，使用反汇编工具（Disassembler）查看内部代码、分析代码结构也属于静态分析的范畴。

我们通过静态分析方法会获得多种信息，这些信息是进行动态分析的重要参考资料，对代码的动态分析非常有帮助。

## 动态分析法

动态分析法是在程序文件的执行过程中对代码进行动态分析的一种方法，它通过调试来分析代码流，获得内存的状态等。通过动态分析法，我们可以在观察文件、注册表（Registry）、网络等的同时分析软件程序的行为。此外，动态分析中还常常使用调试器（Debugger）分析程序的内部结构与动作原理。

在逆向分析代码时，通常先采用静态分析法收集代码相关信息，然后通过收集到的信息推测程序的结构与行为机制。这些推测对动态分析具有非常高的参考价值，能为动态分析提供很多创意。对程序代码进行逆向分析的过程中，灵活使用静态与动态两种分析方法，动静结合，可以极大地提高代码的分析效率，增加分析的准确性，缩短代码分析时间。

我们重点关注call和jmp指令

**CALL 指令**用于调用子程序。执行时，它会将当前指令的下一条指令地址压入堆栈，跳转到目标地址执行子程序。子程序完成后，通过 **RET** 指令从堆栈中弹出返回地址，跳回到调用点继续执行。这种机制使得 **CALL** 非常适合函数调用，因为它能够确保程序在执行完子程序后返回原位置。

**JMP 指令**用于无条件跳转。它直接将程序的执行流跳转到目标地址，而不会保存跳转前的位置。执行 **JMP** 后，程序不会返回到原位置，除非显式使用 **CALL** 或 **JMP** 跳回。它通常用于循环控制、跳过代码段或直接跳转到某个函数。

## 打补丁修改字符串

代码逆向分析中，“打补丁” 操作是不可或缺的重要主题。利用 “打补丁” 技术不仅可以修复已有程序中的 Bug，还可以向程序中添加新功能。“打补丁” 的对象可以是文件、内存，还可以是程序的代码、数据等。我们将使用 “打补丁” 技术把 HelloWorld.exe 程序消息窗口显示的 “Hello World!” 字符串更改为其他字符串

下面介绍 2 种简单的修改字符串的方法

① 直接修改字符串缓冲区（buffer）

② 在其他内存区域生成新字符串并传递给消息函数

### 直接修改字符串缓冲区

![image-20260808131906417](images/image-20260808131906417.png)

MessageBoxA 函数的字符串参数 “Hello World!” 保存在地址 C4005 处的一段缓冲区中，只要修改这段内容，就可以修改 MessageBoxA 函数显示出的字符串。在内存窗口选中要修改的字符串.按 Ctrl+E 快捷键打开编辑窗口

![image-20260808194222759](images/image-20260808194222759.png)

虽然指令保持不变，但原字符串已经被新字符串取代，用作 MessageBoxA () 函数的参数，并且参数的地址仍为 4092A0，只是该地址空间中的内容（字符串）发生了改变。按 F9 键运行程序后，将弹出消息窗口，可以看到显示出的新字符串。

![image-20260808194257844](images/image-20260808194257844.png)

若新字符串长度大于原有字符串，执行覆盖操作时可能损坏字符串后面的数据，所以一定要小心。特别是字符串后面有非常重要的数据时，覆盖操作导致数据损坏就会引发程序内存引用错误

可执行文件保存字符串时一般会给字符串多留出一些空间。所以，如果你的运气足够好，使用更长的字符串覆盖原字符串时，即使原字符串后面的部分空间被侵占，程序仍然能正常运行

上面的调试中，我们通过修改字符串缓冲区更改了程序显示的消息内容，但是这种更改只是暂时的，终止调试（即 HelloWolrd.exe 进程结束）后，程序中的原字符串仍然没有改变。如果想把这种更改永久保存下来，就要把更改后的程序另保存为一个可执行文件

Q. 什么是启动函数？

A. 首先，启动函数（Stub code）不是用户编写的代码，而是编译器自动添加的代码。编译程序时，不同编译器会根据自身特点添加不同启动函数，特别是 EP 代码区域中存在着许多启动函数，它们也被称为启动代码（StartUp code）。调试程序时，我们不需要仔细分析这些启动函数，但是初学者有必要分清程序中哪些是启动函数，哪些是用户代码。希望大家调试时多看一看这些代码，熟悉后就能轻松区分。

Q. 到底什么是 PE 文件，为什么要等到后面才讲解？如果不懂得 PE 文件是否就无法调试？

A. PE 是 Portable Executable 的简称，它是 Windows 操作系统下的可执行文件的格式，主要包含了对文件规格的描述，代码逆向分析技术的初学者学习它会感到非常吃力、无趣。所以我们并没有在前面详细讲解，更重要的是先让大家感受到调试的乐趣，然后再一点点地学习。此外，如果不了解 PE 文件结构的相关知识，将无法进行高级调试。

## 小端序标记法

计算机领域中，字节序（Byte Ordering）是多字节数据在计算机内存中存储或网络传输时各字节的存储顺序，主要分为两大类：**小端序**（Little endian）、**大端序**（Big endian）

```asm
BYTE  b  = 0x12;
WORD  w  = 0x1234;
DWORD dw = 0x12345678;
char  str[] = "abcde";
```

以上代码共 4 种不同大小的数据类型，同一数据按不同字节序存储结果存在差异。 

![image-20260808210127124](images/image-20260808210127124.png)

数据类型为字节型（BYTE）时，其长度为 1 个字节，保存这样的数据时，无论采用大端序还是小端序，字节顺序都是一样的。但是数据长度为 2 个字节以上（含 2 个字节）时，采用不同字节序保存它们形成的存储顺序是不同的。

采用大端序存储数据时，内存地址低位存储数据的高位，内存地址高位存储数据的低位，这是一种最直观的字节存储顺序；

采用小端序存储数据时，地址高位存储数据的高位，地址低位存储数据的低位，这是一种逆序存储方式，保存的字节顺序被倒转。变量 w 与 dw 中的值就能了解大端序与小端序的不同。

再次强调一下，数据为单一字节时，无论采用大端序还是小端序保存，字节存储顺序都一样。只有数据长度在 2 个字节以上时，即数据为多字节数据（multi-bytes）时，选用大端序还是小端序会导致数据的存储顺序不同。字符串 “abcde” 被保存在一个字符（Char）数组 str 中，因为字符数组在内存中是连续的，此时向字符数组存放数据，无论采用大端序还是小端序，存储顺序都相同。

### 大端序和小端序

采用大端序保存多字节数据非常直观，它常用于大型 UNIX 服务器的 RISC 系列的 CPU 中。此外，网络协议中也经常采用大端序方式。了解这些，对从事 x86 系列应用程序的开发人员以及代码逆向分析人员具有非常重要的意义，因为通过网络传输应用程序使用数据时，往往都需要修改字节序。

如果字节序仅有大端序这一种类型，那么就没什么可说的了。但不幸的是，它还包括另一种类型 ——Intel x86 CPU 采用的小端序。所以，对我们这些从事 Windows 程序逆向分析的人来说，切实掌握小端序是十分必要的。小端序采用逆序方式存储数据，使用小端序进行算术运算以及扩展 / 缩小数据时，效率都非常高。

## ia32寄存器

学习程序调试技术前必须掌握 IA-32（Intel Architecture 32 位）寄存器相关内容。寄存器是 CPU 内部的高速存储单元，CPU 访问寄存器的速度远高于访问内存——因为 CPU 与内存之间的物理路径更长，而寄存器集成在 CPU 核心，读写几乎零延迟。

为什么要学寄存器？因为在反汇编和调试时，看到的全是汇编指令，而绝大多数汇编指令都在操作寄存器。遇到不懂的指令就去翻 Intel 提供的用户手册，这是学习汇编最踏实的路径。

### IA-32 寄存器分类

IA-32 是 Intel 的 32 位 CISC 架构，功能丰富，寄存器种类也多。从用途上可以分为以下几类：

![image-20260808222404683](images/image-20260808222404683.png)

- **基本程序运行寄存器**（Basic Program Execution Registers）——编程和调试最常用，也是初学者的重点
- **x87 FPU 寄存器**——浮点运算单元寄存器
- **MMX 寄存器**——多媒体扩展寄存器
- **XMM 寄存器**——流式 SIMD 扩展寄存器
- **控制寄存器**——控制系统级行为
- **内存管理寄存器**——管理分段和分页
- **调试寄存器**——硬件断点支持
- **内存类型范围寄存器**
- **机器特定寄存器**
- **机器检查寄存器**

初学者先掌握基本程序运行寄存器就够了。控制寄存器、内存管理寄存器、调试寄存器等属于进阶内容，在后续调试实践中再逐步深入。

### 基本程序运行寄存器

![image-20260808222512675](images/image-20260808222512675.png)

基本程序运行寄存器是编写和阅读汇编代码时打交道最多的一组寄存器，共 16 个，分为四类：

- **通用寄存器**：32 位，8 个（EAX、EBX、ECX、EDX、ESI、EDI、EBP、ESP）
- **段寄存器**：16 位，6 个（CS、DS、SS、ES、FS、GS）
- **程序状态与控制寄存器**：32 位，1 个（EFLAGS）
- **指令指针寄存器**：32 位，1 个（EIP）

寄存器名前面的字母 `E` 代表 Extended（扩展），意思是这些寄存器在 16 位 CPU（IA-16）时代就已经存在，到了 IA-32 被从 16 位扩展到 32 位。访问时可以只取低 16 位（如 `AX`），也可以用完整的 32 位（如 `EAX`）。

### 通用寄存器

通用寄存器用于数据传送、暂存数据、算术和逻辑运算以及保存结果。每个寄存器 32 位（4 字节），既可以存常数也可以存地址，由具体的汇编指令决定用途。其中部分寄存器有特定的隐含功能。

![image-20260808222553068](images/image-20260808222553068.png)

从图中可以看到，EAX、EBX、ECX、EDX 四个寄存器可以进一步拆分：

- 低 16 位可以独立访问，叫 `AX`/`BX`/`CX`/`DX`
- 这 16 位又能拆成两个 8 位：高 8 位 `AH`/`BH`/`CH`/`DH`，低 8 位 `AL`/`BL`/`CL`/`DL`

以 EAX 为例：完整 32 位是 `EAX`（位 0\~31），低 16 位是 `AX`（位 0\~15），`AX` 的高 8 位是 `AH`（位 8\~15），低 8 位是 `AL`（位 0\~7）。修改 `AL` 会同时影响 `AX` 和 `EAX`，因为它们是重叠的，不是独立的存储单元。

而 EBP、ESI、EDI、ESP 只能以 32 位或低 16 位访问，不能再拆成 8 位。

各通用寄存器的特定用途：

| 寄存器  | 名称           | 主要用途                      |
| ------- | -------------- | ----------------------------- |
| **EAX** | 累加器         | 算术运算                      |
| **EBX** | 基址寄存器     | DS 段中的数据指针             |
| **ECX** | 计数器         | 字符串操作和循环的计数器      |
| **EDX** | 数据寄存器     | I/O 指针、乘除法辅助          |
| **EBP** | 扩展基址指针   | SS 段中栈内数据指针，建立栈帧 |
| **ESI** | 源变址寄存器   | 字符串操作的源地址            |
| **EDI** | 目的变址寄存器 | 字符串操作的目的地址          |
| **ESP** | 栈指针寄存器   | 始终指向栈顶                  |

EAX、EBX、ECX、EDX 四个寄存器常用于算术运算（`ADD`、`SUB`、`XOR`、`OR` 等），也用于存储常量和变量。有些指令直接绑定特定寄存器：`MUL`/`DIV` 隐含使用 EAX 和 EDX，`LODS`/`STOS`/`MOVS` 使用 ESI 和 EDI，`LOOP` 指令每轮自动递减 ECX。在 Win32 API 调用中，函数返回值放在 EAX 里。

Win32 API 函数内部会使用 ECX 和 EDX，调用 API 前如果这两个寄存器里存着有用的数据，要先备份（`PUSH` 到栈上），否则会被覆盖。

EBP 用于建立栈帧。函数被调用时，通常先 `PUSH EBP` 保存调用者的 EBP，再 `MOV EBP, ESP` 把当前栈顶设为新帧基址，之后通过 `EBP + 偏移` 访问参数和局部变量。ESP 在 `PUSH`、`POP`、`CALL`、`RET` 时自动变化，始终指向栈顶，不应挪作他用。

ESI 和 EDI 配合字符串指令使用：`LODS` 从 ESI 指向的地址读数据到 EAX，`STOS` 把 EAX 写到 EDI 指向的地址，`MOVS` 在 ESI 和 EDI 之间搬数据，配合 `REP` 前缀可以用 ECX 控制重复次数。

### 段寄存器

![image-20260808222727500](images/image-20260808222727500.png)

段的概念来自 IA-32 的内存管理模型。在保护模式下，CPU 通过分段机制实现内存保护：段寄存器里存的是段选择子（Selector），CPU 用它去查段描述符表（GDT/LDT），拿到段基址、段限长和访问权限，再计算出线性地址。如果开启了分页，线性地址还要经过页表翻译成物理地址；如果没开分页，线性地址就是物理地址。

6 个段寄存器都是 16 位：

| 寄存器 | 名称   | 用途                           |
| ------ | ------ | ------------------------------ |
| **CS** | 代码段 | 指向当前正在执行的代码段       |
| **SS** | 栈段   | 指向当前栈段（配合 ESP/EBP）   |
| **DS** | 数据段 | 指向默认数据段                 |
| **ES** | 附加段 | 额外数据段，字符串操作的目的段 |
| **FS** | 数据段 | 附加数据段，Windows 下指向 TEB |
| **GS** | 数据段 | 附加数据段                     |

段寄存器的细节比较复杂，初学阶段不必深究。现代操作系统（Windows、Linux）在保护模式下大多使用平坦内存模型（Flat Model），各段基址都设为 0、段限长设为 4GB，分段机制实际上被绕过了。但在调试时，FS 寄存器很重要：它指向线程环境块（TEB），通过 FS 可以访问 SEH（结构化异常处理）、TEB 和 PEB（进程环境块），这些是高级调试和逆向的关键结构。

### 程序状态与控制寄存器 EFLAGS

![image-20260808222800545](images/image-20260808222800545.png)

上图展示了分段内存模型：段寄存器（左）通过段描述符（中）映射到线性地址空间（右）中的不同区域——栈、代码、数据等。FS 和 GS 在实际使用中可以指向特殊段（如 TEB 所在的段）。

EFLAGS 是标志寄存器，32 位，从 16 位的 FLAGS 扩展而来。它的每一位都有独立含义，值为 1 表示"置位"（On/True），值为 0 表示"清除"（Off/False）。有的位由 CPU 根据指令执行结果自动设置，有的位可以由程序指令修改。

EFLAGS 有 32 位，先掌握三个最关键的标志位：

| 标志   | 名称                      | 含义                         |
| ------ | ------------------------- | ---------------------------- |
| **ZF** | 零标志（Zero Flag）       | 运算结果为零时置 1，否则清 0 |
| **OF** | 溢出标志（Overflow Flag） | 有符号数运算溢出时置 1       |
| **CF** | 进位标志（Carry Flag）    | 无符号数运算进位/借位时置 1  |

### 指令指针寄存器 EIP

EIP 是指令指针寄存器，32 位，从 16 位的 IP 扩展而来。它保存的是 CPU 下一条要执行的指令地址。

CPU 的工作循环是：读取 EIP 指向的指令 → 送入指令缓冲区 → EIP 自动增加当前指令的字节长度 → 执行指令 → 重复。正常顺序执行时，EIP 就这样一直递增。

EIP 不能像通用寄存器那样用 `MOV` 直接修改。改变 EIP 的方式都是间接的：

- `JMP`、`Jcc`（条件跳转）直接设置 EIP
- `CALL` 把返回地址压栈后跳转
- `RET` 从栈中弹出地址写回 EIP
- 中断和异常也会修改 EIP

调试器设断点时，实际上就是在 EIP 指向的位置暂停，让你查看那一刻所有寄存器的状态。

## 栈

栈（Stack）的用途广泛，通常用于存储局部变量、传递函数参数、保存函数返回地址等。调试程序时需要不断查看栈内存，所以掌握栈的运行原理对于提升程序调试水平是非常有帮助的。

栈内存在进程中的作用如下：

(1) 暂时保存函数内的局部变量。

(2) 调用函数时传递参数。

(3) 保存函数返回后的地址。

栈其实是一种数据结构，它按照 FILO（First In Last Out，后进先出）的原则存储数据。一会通过一个示例来证明这一点。

### 栈的特征

![image-20260808224833241](images/image-20260808224833241.png)

一个进程中，栈顶指针（ESP）初始状态指向栈底端。执行 PUSH 命令将数据压入栈时，栈顶指针就会上移到栈顶端。执行 POP 命令从栈中弹出数据时，若栈为空，则栈顶指针重新移动到栈底端。换言之，栈是一种由高地址向低地址扩展的数据结构，图 5-1 中，栈是由下往上扩展的。由于栈具有这种特征，所以我们常常说 “栈是逆向扩展的”，向栈中压数据就像一层层砌砖，每向上砌一层，砖墙就增高一点儿。

## 栈帧

我们将学习栈帧（Stack Frame）相关知识，栈帧在程序中用于声明局部变量、调用函数。理解了栈帧，就能轻松掌握保存在其中的函数参数和局部变量，这对我们调试代码也是很有帮助的。

简言之，栈帧就是利用 **EBP**（栈帧指针，请注意不是 ESP）寄存器访问栈内局部变量、参数、函数返回地址等的手段。通过前面关于 IA-32 寄存器的学习我们知道，ESP 寄存器承担着栈顶指针的作用，而 EBP 寄存器则负责行使栈帧指针的职能。程序运行中，ESP 寄存器的值随时变化，访问栈中函数的局部变量、参数时，若以 ESP 值为基准编写程序会十分困难，并且也很难使 CPU 引用到准确的地址。所以，调用某函数时，先要把用作基准点（函数起始地址）的 ESP 值保存到 EBP，并维持在函数内部。这样，无论 ESP 的值如何变化，以 EBP 的值为基准（base）能够安全访问到相关函数的局部变量、参数、返回地址，这就是 EBP 寄存器作为栈帧指针的作用。

接下来看看栈帧对应的汇编代码。

借助栈帧技术管理函数调用时，无论函数调用的深度有多深、多复杂，调用栈都能得到很好的管理与维护。

- 在栈中保存函数返回地址是系统安全隐患之一，攻击者使用缓冲区溢出技术能够把保存在栈内存的返回地址更改为其他地址。

### main函数及栈帧

函数`main()`是程序开始执行的地方,`main()`函数的起始地址为401020

开始执行`main()`函数时栈的状态如图所示。从现在开始要密切关注栈的变化

![image-20260809203654751](images/image-20260809203654751.png)

![image-20260809203732937](images/image-20260809203732937.png)

当前ESP的值为1AFF30,EBP的值为16FF74,切记地址401250保存在ESP(1AFF30)中,它是main()函数执行完毕后要返回的地址

```asm
00401020 PUSH EBP        ; # main()
```

PUSH 是一条压栈指令，上面这条 PUSH 语句的含义是 “把 EBP 值压入栈”。`main()`函数中，EBP 为栈帧指针，用来把 EBP 之前的值备份到栈中（`main()`函数执行完毕，返回之前，该值会再次恢复）。

```asm
00401021 MOV EBP,ESP
```

MOV 是一条数据传送命令，上面这条 MOV 语句的命令是 “把 ESP 值传送到 EBP”。换言之，从这条命令开始，EBP 就持有与当前 ESP 相同的值，并且直到`main()`函数执行完毕，EBP 的值始终保持不变。也就是说，我们通过 EBP 可以安全访问到存储在栈中的函数参数与局部变量。执行完 401020 与 401021 地址处的两条命令后，函数`main()`的栈帧就生成了（设置好 EBP 了）。

### main设置局部栈帧

下面分析变量声明及赋值语句

```cpp
long a = 1, b = 2;
```

main () 函数中，上述语句用于在栈中为局部变量 (a,b) 分配空间，并赋初始值

那么函数中声明的变量 a、b 是如何在函数栈中生成的，又是如何管理的呢？

```asm
00401023 SUB ESP,8
```

SUB 是汇编语言中的一条减法指令，上面这条语句用来将 ESP 的值减去 8 个字节。执行该条命令之前，ESP 的值为 1AFF2C(因为push ebp,即1AFF30-4)，减去 8 个字节后，变为 1AFF24。那么为什么要将 ESP 减去 8 个字节呢？从 ESP 减去 8 个字节，其实质是为函数的局部变量（a 与 b ）开辟空间，以便将它们保存在栈中。由于局部变量 a 与 b 都是 long 型（长整型），它们分别占据 4 个字节大小，所以需要在栈中开辟 8 个字节的空间来保存这 2 个变量。

![image-20260809212010964](images/image-20260809212010964.png)

使用 SUB 指令从 ESP 中减去 8 个字节，为 2 个函数变量开辟好栈空间后，在 main () 内部，无论 ESP 的值如何变化，变量 a 与 b 的栈空间都不会受到损坏。由于 EBP 的值在 main () 函数内部是固定不变的，我们就能以它为基准来访问函数的局部变量了。继续看如下代码。

```asm
00401026 MOV DWORD PTR SS:[EBP-4],1  ; [EBP-4] = local 'a'
0040102D MOV DWORD PTR SS:[EBP-8],2  ; [EBP-8] = local 'b'
```

对于刚刚接触汇编语言的朋友来说，上面两条命令中的 `DWORD PTR SS:[EBP-4]` 部分可能略显陌生。其实没什么难的，只要把它们看作类似于 C 语言中的指针就可以了。

| 汇编语言             | C 语言             | 类型转换         |
| -------------------- | ------------------ | ---------------- |
| DWORD PTR SS:[EBP-4] | `*(DWORD*)(EBP-4)` | DWORD (4 个字节) |
| WORD PTR SS:[EBP-4]  | `*(WORD*)(EBP-4)`  | WORD (2 个字节)  |
| BYTE PTR SS:[EBP-4]  | `*(BYTE*)(EBP-4)`  | BYTE (1 个字节)  |

上面这些指针命令很难用简洁明了的语言描述出来，简单翻译一下就是，地址 EBP-4 处有一个 4 字节大小的内存空间

提示

`DWORD PTR SS:[EBP-4]` 语句中，SS 是 Stack Segment 的缩写，表示栈段。由于 Windows 中使用的是段内存模型（Segment Memory Model），使用时需要指出相关内存属于哪一个区段。其实，32 位的 Windows OS 中，SS、DS、ES 的值皆为 0，所以采用这种方式附上区段并没有什么意义。因 EBP 与 ESP 是指向栈的寄存器，所以添加上了 SS 寄存器。

### 设置add函数的局部变量

```cpp
long x = a, y = b;
```

上面一行语句声明了 2 个长整型的局部变量 (x, y)，并使用 2 个形式参数 (a, b) 分别为它们赋初始值。重点关注形式参数与局部变量在函数内部的栈寻址方式。

```asm
00401003  SUB ESP,8
```

这条指令含义：在栈内存中为局部变量 x、y 开辟 8 个字节的栈空间。

```asm
00401006  MOV EAX,DWORD PTR SS:[EBP+8]  ; [EBP+8] = 形参a
00401009  MOV DWORD PTR SS:[EBP-8],EAX  ; [EBP-8] = 局部变量x
0040100C  MOV ECX,DWORD PTR SS:[EBP+C]  ; [EBP+C] = 形参b
0040100F  MOV DWORD PTR SS:[EBP-4],ECX  ; [EBP-4] = 局部变量y
```

add 函数的栈帧生成之后，EBP 基准地址固定不变：

`[EBP+8]`、`[EBP+C]` 指向传入参数 a、b；

`[EBP-8]`、`[EBP-4]` 指向 add 函数的 2 个局部变量 x、y。

### add运算

```cpp
return (x + y);
```

此语句用于返回两个局部变量之和

```asm
00401012    MOV EAX,DWORD PTR SS:[EBP-8]  ; [EBP-8] = local x
```

上述MOV语句中，变量x的值被传送到EAX。

```asm
00401015    ADD EAX,DWORD PTR SS:[EBP-4]  ; [EBP-4] = local y
```

ADD指令为加法指令，上面这条语句中，变量y（[EBP-4]=2）与EAX原值（x）相加，且运算结果被存储在EAX中，运算完成后EAX中的值为3。

### 删除函数add的栈帧及函数执行完毕

```cpp
return (x + y);
```

同样对应如上代码

执行完加法运算后，要返回函数 add ()，在此之前先删除函数 add () 的栈帧。

```asm
00401018  MOV ESP,EBP
```

上面这条命令把当前 EBP 的值赋给 ESP，与地址 401001 处的 `MOV EBP,ESP` 命令相对应。在地址 401001 处，`MOV EBP,ESP` 命令把函数 add () 开始执行时的 ESP 值（1AFF14）放入 EBP。函数执行完毕后，使用地址 401018 处的 `MOV ESP,EBP` 命令再把 EBP 中的值恢复到 ESP 中。

**提示：**

执行完上面的命令后，地址 401003 处的 `SUB ESP,8` 命令就会失效，即函数 add () 的 2 个局部变量 x、y 不再有效。

```asm
0040101A  POP EBP
```

上面这条命令用于恢复函数 add () 开始执行时保存到栈中的 EBP 值，它与 401000 地址处的 `PUSH EBP` 命令对应。EBP 值恢复为 1AFF2C，它是 main () 函数的 EBP 值。至此，函数 add () 的栈帧就被删除了。

应用程序采用上述方式管理栈，无论有多少函数被嵌套调用，栈都能得到较好的维护，不会崩溃。但由于函数的局部变量、参数、返回地址等是一次性保存到栈中的，利用字符串函数的漏洞等很容易引起栈缓冲区溢出，最终导致程序或系统崩溃。

### 从栈中删除add函数的参数

现在，程序执行流已经重新返回 main () 函数中,接下来便执行这条指令

使用 ADD 命令将 ESP 加上 8，为什么突然要把 ESP 加上 8 呢？请看栈窗口，地址 1AFF1C与 1AFF20 处存储的是传递给函数 add () 的参数 a 与 b。函数 add () 执行完毕后，就不再需要参数 a 与 b 了，所以要把 ESP 加上 8，将它们从栈中清理掉（参数 a 与 b 都是长整型，各占 4 个字节，合起来共 8 个字节）。

**提示**

被调函数执行完毕后，函数的调用者（Caller）负责清理存储在栈中的参数，这种方式称为 cdecl 方式；反之，被调用者（Callee）负责清理保存在栈中的参数，这种方式称为 stdcall 方式。这些函数调用规则统称为调用约定（Calling Convention），这在程序开发与分析中是一个非常重要的概念。
